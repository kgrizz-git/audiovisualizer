# Frontend, Design, UX, And UI Inventory

Use this file when the project has a user interface, design system, prototype, website, game, dashboard, or product experience.

## Design And Product Sources

- Figma for source designs, components, tokens, and comments.
- Google Stitch for AI-assisted UI exploration where useful.
- Existing product screenshots or brand guidelines.
- Storybook for component catalogs.
- Design tokens where the project needs cross-platform consistency.

## Design System References

Use these as references, not as defaults. Choose based on platform, product domain, accessibility needs, and implementation stack.

- Material Design 3: https://m3.material.io/
- Carbon Design System: https://carbondesignsystem.com/designing/get-started/
- Apple Human Interface Guidelines and design hub: https://developer.apple.com/design/

- Apple Icon Composer: https://developer.apple.com/icon-composer/

## Frontend Tooling

- Playwright for end-to-end flows, screenshots, and visual regression checks.
- Axe or equivalent accessibility checks.
- Lighthouse for web quality checks.
- Storybook test runner where Storybook is used.
- Component libraries appropriate to the framework and product tone.

## UX Review Prompts

Ask future agents to review:

- Primary user workflows.
- Empty, loading, error, and success states.
- Accessibility.
- Responsiveness.
- Copy clarity.
- Navigation and information architecture.
- Visual consistency with the product domain.

## Selection Guidance

Do not choose a visual system before understanding the audience and product. Operational tools usually need dense, calm, scannable interfaces. Marketing sites, portfolios, games, and prototypes may need more expressive visual systems.
